What it does

A laptop combines input, processing, memory, storage, power, cooling and display systems in one portable computer.

Simple analogy

Think of the laptop as a small workshop: input devices give instructions, processing units work on them, memory holds active information, and the display shows results.

Engineering view

The parts communicate through electrical interfaces and buses. The operating system and firmware coordinate access to the hardware.

A quick architecture lesson

What are you actually seeing?

When you press a key, laptop keyboard hardware detects a switch state. Many laptop keyboards are scanned as a row-and-column matrix by firmware in an embedded controller (the exact design varies by manufacturer and model). The controller reports key information to the host. The operating system processes the input and the browser receives a keydown event. This simulator can read browser event fields such as event.key and event.code — it cannot read the raw voltage, keyboard matrix lines, CPU pins, cache traffic or RAM electrical signals.

The 3D route before the browser event is an educational model of a typical input path. The CPU, RAM and GPU stages are also simplified teaching models: the webpage does not trace the actual machine instructions executed by your laptop's processor. At the last stage, the browser really does update this simulator's visual output, while the exact GPU/compositor work is managed by the browser and operating system.

  • Beginner mode: plain-language explanations and the high-level data path.
  • Advanced mode: key codes, binary/hex values, byte-level data and illustrative CPU pipeline telemetry.
  • 3D controls: drag to rotate, scroll to zoom, click a component to inspect it, and use Exploded view to separate the internal parts.

For an internal keyboard, the EC and host connection can vary (for example, platform-specific embedded-controller interfaces). External USB keyboards use the USB HID path. The diagram is intentionally generic rather than claiming every laptop has the same wiring.

Learning references: MDN KeyboardEvent documentation · Intel Open EC Firmware keyboard matrix documentation · Linux kernel HID documentation.
